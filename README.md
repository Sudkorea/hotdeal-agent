# Hotdeal Agent

**할인상품을 모아 알림을 고르고, 내 피드백을 다음 평가에 반영하는 개인용 도구입니다.**

2025년 12월부터 개발했고, 사용자는 본인 한 명입니다. 문제 정의·기획·설계 검토·운영과 적용 승인을 맡았으며, 코드 구현은 AI 코딩 도구와 협업했습니다.

이 저장소에는 구조와 운영 사례를 소개하는 문서가 있습니다. 실행 코드와 운영 DB는 포함하지 않습니다. 아래 기능과 수치는 **2026-07-13 기록 기준**입니다.

[동작 상세](docs/WORKFLOW.md) · [운영 사례와 수치](docs/OPERATIONS.md)

## 왜 만들었나?

새벽에 240만 원대 태블릿이 가격 오류로 83만 원에 올라온 적이 있습니다. 깨어 있었는데도 소식을 받지 못했습니다. 다음에는 직접 게시판을 확인하지 않아도 필요한 할인 정보를 받을 수 있도록 만들었습니다.

## 어떻게 사용하나?

할인 알림을 받고 평점이나 자연어로 피드백을 남깁니다. 특정 상품은 `!찾아줘 <상품> [목표가]`로 요청하고, `!목록`으로 조회하거나 `!그만 <상품>`으로 해제합니다. 새 수집원 편입과 알림 기준 변경은 제안을 확인한 뒤 승인합니다.

## 전체 흐름

```text
할인 글 수집
    ↓
가격·할인액·적용 조건 정리
    ↓
점수 평가·가격 근거 검사
    ├─ 즉시 알림
    ├─ 정기 요약
    └─ 저장만

사용자 피드백 → 원문 저장 → 구조화·검증 → 선호 반영
알림·미알림 기록 → 일일 회고 → 변경 제안·검증 → 사람 승인 → 기준 변경
```

수집·알림·피드백의 상태는 SQLite에 저장하고, 발송 여부의 판단 사유는 `decision_log`에 남깁니다. 지정 상품 검색, 새 수집원 발굴, 주간 조정은 이 흐름을 보완하는 별도 작업입니다.

### LLM, 규칙, 사람은 무엇을 맡나?

| 구분 | 맡는 일 |
|---|---|
| **LLM** | 자연어 피드백 구조화, 새 수집원 후보 조사, 기록에 기반한 알림 임계값 변경안 생성 |
| **규칙·검증 코드** | 수집 도구 선택, 스키마·금액 검사, 알림 조건 판정, 실패 소스 격리, 변경 가능한 파라미터와 범위 검사 |
| **사람** | 평가·선호 피드백 입력, 신규 소스의 운영 편입과 알림 임계값 변경 승인 |

피드백은 검증 후 선호에 반영합니다. 반면 새 소스 편입과 알림 임계값 변경은 사람 승인 뒤 적용합니다.

## 자세히 볼 두 경로

**피드백 원문 저장과 LLM 추출을 나눴습니다.** 원문을 먼저 저장하고 추출이 실패하면 재처리할 수 있게 했습니다. 당시 기록에는 추출 실패 8건을 다시 처리해 적용한 사례가 있습니다. [피드백 상태 흐름](docs/WORKFLOW.md#feedback) · [복구 기록과 한계](docs/OPERATIONS.md#feedback-recovery)

**알림 기준은 변경안을 받은 뒤 승인합니다.** 일일 회고와 결정 로그를 바탕으로 주간 변경안을 만들고, 허용된 파라미터·값의 범위·변경폭을 검사합니다. 당시 첫 실행에서 임계값 하향 2건이 제안됐지만 승인 대기 상태였습니다. [변경 제안과 적용](docs/WORKFLOW.md#tuning)

## 기술 구성

Python으로 수집·검증·작업 흐름을 구성하고 SQLite에 상태를 저장합니다. 스케줄러와 피드백 HTTP 서버를 사용하며, Discord 게이트웨이 런타임은 Zig 기반입니다. LLM 호출은 자체 런타임의 `run` API를 거칩니다. LangGraph를 사용한 구현은 아닙니다.

수집·발송량, 테스트 규모와 피드백의 한계는 [운영 기록](docs/OPERATIONS.md)에서 볼 수 있습니다.
